# 구현 및 검증 기록

최초 RAW 검증: 2026-10-01, Windows 11 x64. 이 문서는 구현 결과와 명세의 미충족 수용 기준을 구분합니다. 일반 이미지 지원을 추가한 뒤의 검증은 아래 별도 항목에 기록합니다.

## 검증 환경

- CPU: AMD Ryzen 7 7730U with Radeon Graphics
- Python 3.12.14 x64
- rawpy 0.25.1 / 실제 LibRaw 0.21.4
- NumPy 2.2.6, Pillow 11.3.0, PySide6 6.9.2, tifffile 2025.9.20, ExifRead 3.5.1
- 전체 의존성: `requirements-lock.txt`
- 실측 성능과 메모리: `benchmark.json` 참고. 처리 엔진의 측정치이며 모든 PC의 성능을 보장하지 않습니다.

## 최종 결과 요약

일반 이미지 지원 추가 후 자동 회귀 테스트는 **127개 모두 통과**했습니다. JPEG·PNG·TIFF·WebP·BMP의 실제 합성 파일로 읽기·미리보기·저장을 확인했습니다. 대소문자 혼합 확장자, 혼합 형식 선택과 폴더 처리, EXIF 방향 1~8, 회색조·투명도, ICC 변환, 16비트 TIFF 계조 보존, 원본 해시 보호를 검사합니다. BMP V5 내장 ICC와 회색조 TIFF의 premultiplied alpha도 포함합니다.

일반 이미지와 RAW는 입력 처리를 구분하며, 기존 RAW 레시피와 카메라 제한을 유지합니다. 지원하지 않는 16비트 PNG·특수 TIFF·다중 프레임 입력은 오류로 안내합니다. 형식별 범위는 README의 **지원하는 입력**에 정리했습니다. 자동 테스트에서 생성한 사진과 출력물은 저장소에 포함하지 않습니다.

갱신한 Windows 실행 파일에서도 합성 일반 이미지 5장과 실제 Sony a6400 RAW 1장을 한 번에 처리했습니다. 6장 모두 16비트 TIFF·sRGB ICC·Orientation=1·레시피 저장에 성공했고 원본 SHA-256은 유지됐습니다. 별도 작업 프로세스를 사용하는 실제 GUI에서 EXIF 회전이 있는 JPEG 미리보기도 확인했습니다. 자세한 결과는 `raster-validation.json`, 실행 파일 해시는 `distribution.json`에 기록합니다.

최초 RAW 구현의 자동 회귀 테스트 **60개가 모두 통과**했습니다. 실제 RAW 2장의 정상 처리, 손상 입력의 오류 격리, 원본 해시 보존을 확인했습니다.

동일한 6024×4024 RAW에 시네마/다큐멘터리 스타일을 번갈아 적용한 20회 측정:

| 측정 항목 | 결과 | 측정 범위 |
|---|---:|---|
| 최초 미리보기 | 18.763초 | 캐시 없는 첫 실행 1회 |
| 새로운 스타일 미리보기 | 10.205초 | RAW 기본 현상 캐시 재사용 1회 |
| 동일 설정 미리보기 | 0.056~0.073초 | PNG 캐시 재사용 18회 |
| 원본 해상도 JPEG | P95 10.016초 | 20회 모두 성공, 각 8.485~11.219초 |
| 엔진 프로세스 최대 작업 메모리 | 약 916MiB | Windows PeakWorkingSetSize, GUI 제외 |

위 결과는 실제 사진 한 장을 20회 반복한 성능 측정입니다. 서로 다른 RAW 20장의 수용 시험과 구분합니다. 최초 미리보기 5초와 새 스타일 전환 0.3초 목표는 미달이며, JPEG P95도 10초 기준을 소폭 초과했습니다. RAM은 약 15.35GiB로 측정됐습니다.

## 실제 RAW 입력

[Photography Blog의 Sony a6400 공개 다운로드 샘플](https://www.photographyblog.com/reviews/sony_a6400_review) 중 다음 두 파일을 사용했습니다. 테스트 사진과 변환물은 앱 배포본에 포함하지 않습니다.

| 파일 | 카메라 | ISO | SHA-256 |
|---|---|---:|---|
| sony_a6400_01.arw | ILCE-6400 | 320 | d02004c1b918a3ac17718171a9dcab1c0b9e91ff0d4516106c675e44f87b6be4 |
| sony_a6400_03.arw | ILCE-6400 | 160 | e3e3286c2dde3c2c1a546e532fb20141aa0e1986fd97f38b48a8b06e05c39fe3 |

LibRaw의 유효 이미지 영역은 두 파일 모두 6024×4024입니다. 실제 원본을 읽고 현상하여 JPEG와 16비트 RGB TIFF를 저장합니다. 사용자 사진과 고감도·세로 방향을 포함한 20장 이상 수용 시험은 추가로 필요합니다.

## 확인 항목

- 사면체 보간의 여섯 구간, RGB 축 순서, 단위 LUT, 손상·누락·해시 불일치 LUT 거절.
- 고정 색변환 행렬, LibRaw ProPhoto D65 출력의 표준 ProPhoto D50 정규화, 회색 계조, sRGB 전송함수 왕복, NaN 방지.
- 강도 0의 기본 현상 일치, 흑백 스타일의 RGB 채널 일치, 추가 보정 중립값 일치.
- 입자의 seed 재현성, 원본 좌표 기준 수평·수직 타일 연결, 출력 크기 변경.
- JPEG 및 TIFF에 ICC·Orientation=1·허용 촬영 EXIF 기록. TIFF RGB `uint16` 재읽기. GPS와 일련번호 제외.
- 파일 충돌 시 새 이름, 원본 폴더 출력 차단, 변경된 원본 차단, 저장 중 원본 재검증.
- 레시피 실패 시 부분 완료, 배치에서 개별 실패 후 다음 사진 계속 처리, 취소 처리.
- 사진별 20회 undo/redo, 중복·100장 제한, 대기열 설정 복사본 고정, 프로젝트 복구, 결과 파일 해시 검사.
- Qt 화면의 한글 표시, 흑백 스타일의 채도 비활성화, 오래된 미리보기 결과 무시, Windows 배포본 모듈·스타일 로드.

전체 자동 테스트 결과는 `test-results.xml`에 기록합니다. 합성 배열과 임시 파일을 사용하는 검사는 실제 RAW 20장 시험을 대체하지 않습니다.

## 증거 파일

- `engine-validation.json`: 실제 원본 SHA-256, JPEG/TIFF, 미리보기 일치 검사.
- `additional-results.json`: 두 번째 RAW, 손상 파일 포함 배치, 입자 재현성.
- `benchmark.json`: 동일 RAW의 반복 처리 실측과 P95.
- `test-results.xml`: 자동 회귀 검사 결과.
- `raster-validation.json`: 일반 이미지 지원 추가 후 배포본의 혼합 형식 처리와 GUI 검증.
- `distribution.json`: 갱신한 실행 파일 SHA-256 및 배포본 검사 요약.

로컬 검증 폴더의 스크린샷은 실제 GUI 렌더 결과입니다. 테스트 사진·변환 결과·스크린샷은 GitHub 저장소에 포함하지 않습니다.

## 남은 수용 시험과 한계

1. **색감 검증:** 통제된 참고 사진과 촬영 자료가 없어 보정용 40장/검증용 20장 평가를 수행하지 않았습니다. 모든 프리셋은 필름 느낌을 위한 초기 스타일입니다.
2. **RAW 다양성:** 사용자 실제 RAW 20장, 고감도·밝은 하늘·세로 회전·촬영 모드별 비트 심도 검증이 필요합니다. 코드에서 RAW가 항상 14비트라고 가정하지 않습니다.
3. **성능:** 최초 미리보기 5초, 새 스타일 전환 0.3초, 전체 JPEG 10초 목표는 일부 실측에서 초과했습니다. 동일 설정의 미리보기 캐시는 빠르게 재사용됩니다. 각 20회 반복 결과와 첫 처리 시간을 구분합니다.
4. **메모리:** 디스크 LRU 5GB와 메모리 매핑을 사용합니다. 별도 작업 프로세스는 한 번에 하나만 처리합니다. 전체 GUI+엔진 프로세스 합산 3GB 수용 기준은 별도 장시간 관찰이 필요합니다.
5. **미리보기 색차:** 전체 TIFF 축소와 미리보기의 RGB 차이를 측정했습니다. ΔE00 평균≤1/P95≤3 기준의 정식 색차 평가는 아직 수행하지 않았습니다.
6. **호환성:** Pillow와 tifffile로 결과를 다시 읽었습니다. 서로 다른 외부 사진 뷰어 두 개에서의 육안 호환성 검사는 남아 있습니다.
7. **대량 처리:** 목록 100장 제한과 개별 오류 격리를 자동 검사했습니다. 실제 ARW 100장 중 1장 손상인 장시간 배치는 아직 실행하지 않았습니다.

미검증 항목은 추가 측정과 평가를 마친 뒤 결과를 기록합니다.
