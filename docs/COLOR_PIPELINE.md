# 색 처리와 초기 스타일

## 버전과 입력 계약

기본 현상 버전과 모든 포함 스타일 버전은 `1.0.0`이다. 색 처리 함수는 `film_lab/color.py`, 스타일 로딩과 보간은 `film_lab/profiles.py`에 있다. GUI, 미리보기, 저장은 이 함수를 공유한다.

RAW 엔진은 LibRaw/rawpy에서 촬영 WB와 노출을 적용한 **선형 LibRaw ProPhoto RGB, 16비트** 데이터를 받아 `float32`의 0~1로 정규화한다. LibRaw는 이 출력의 백색점을 D65로 명명한다. `normalize_libraw_prophoto()`에서 고정 행렬로 **표준 ProPhoto RGB D50 좌표**로 변환한 다음 기본 현상에 전달한다. 중간 색 처리와 축소에서는 8비트 변환을 하지 않는다. JPEG를 인코딩할 때만 8비트로 양자화한다. TIFF는 마지막에 16비트 정수로 양자화한다.

색공간 변환의 입력은 이미 카메라 색 변환이 완료된 RGB이다. 이 함수에 센서 모자이크 데이터, 내장 JPEG, 감마가 적용된 ProPhoto를 전달하면 안 된다.

### LibRaw의 ProPhoto D65와 표준 D50 좌표

고정 배포본 rawpy 0.25.1에 포함된 LibRaw 0.21.4의 `convert_to_rgb()`는 `output_color=4`를 **ProPhoto D65**라고 부르고, 내부 선형 sRGB 카메라 변환에 `prophoto_rgb` 행렬을 곱한다. [공식 처리 코드](https://raw.githubusercontent.com/LibRaw/LibRaw/0.21.4/src/postprocessing/postprocessing_utils_dcrdefs.cpp)

이 좌표는 D65로 색순응한 ProPhoto 원색을 사용한다. 표준 ProPhoto D50 좌표와 거의 같지만, 상수의 차이까지 명시적으로 처리하기 위해 다음 변환을 고정한다.

`N = inverse(ProPhoto→XYZ D50) × inverse(Bradford D50→D65) × LibRaw(sRGB→XYZ D65) × inverse(LibRaw(sRGB→ProPhoto))`

LibRaw의 두 행렬은 버전 0.21.4의 [`colorconst.cpp`](https://raw.githubusercontent.com/LibRaw/LibRaw/0.21.4/src/tables/colorconst.cpp)를 기준으로 한다. 위 식으로 미리 계산한 행렬을 `float32` 상수로 저장한다. 정규화 버전은 `1.0.0`이며, 행렬의 little-endian float32 바이트에서 계산한 SHA-256을 RAW 처리 기록과 기본 현상 캐시 키에 포함한다. 디코더의 D65 공간과 정규화 후 D50 작업 공간을 별도로 기록한다.

정규화 행렬과 단위행렬의 최대 계수 차이는 약 `6.32×10⁻⁵`이다. 그 차이가 작더라도 단순히 디코더 출력을 D50으로 이름만 바꾸지 않는다. 정규화 단계의 작은 음수 또는 1 초과 값은 유지하여 기본 현상의 명암 곡선과 색역 압축에서 처리한다. 추가 화이트밸런스를 적용하는 단계는 아니다.

테스트는 공식 LibRaw 행렬로 변환한 RGB 원색, 회색 램프, 임의 RGB를 다시 sRGB로 돌렸을 때 오차가 `1×10⁻⁶` 이내인지 확인한다. 중립색의 최종 기본 렌더도 같은 허용치에서 의도한 톤 곡선과 일치한다.

## 기본 현상

`baseline_render()`의 처리 순서는 다음과 같다.

1. 선형 ProPhoto RGB → XYZ D50.
2. 고정 Bradford 행렬로 D50 → D65 색순응.
3. XYZ D65 → 선형 sRGB.
4. sRGB 선형 휘도 `Y = 0.2126R + 0.7152G + 0.0722B`에 고정 곡선 `T(Y) = min(1, 1.25Y / (1 + 0.25Y))`을 적용하고 RGB에 휘도 비율을 곱한다.
5. 같은 휘도의 회색을 향해 채도를 완만하게 줄여 sRGB 색역에 넣는다.
6. 표준 sRGB 전송함수를 한 번 적용한다.

행렬 상수와 곡선은 소스에 고정되어 있다. 곡선 정의는 `data/profiles/baseline/curve.json`에도 기록한다. 곡선의 휘도 축은 sRGB/XYZ Y이므로 색 변환 후 적용한다. 이 순서를 바꾸면 기본 현상 버전을 올려야 한다.

색역 압축은 현재 색상 방향에서 허용되는 최대 채도의 80% 지점부터 지수 곡선으로 작동한다. 채널별로 바로 잘라내는 대신 휘도를 유지하며 색역 경계에 접근한다. 최종 0~1 제한은 수치 오차와 극단값을 보호한다. 센서 또는 rawpy의 16비트 출력에서 이미 포화된 정보를 복원하지 않는다.

## 컬러 스타일과 보간

네 가지 컬러 스타일은 33×33×33 `.cube` 파일이다. 입력과 출력 모두 **D65, sRGB 전송함수가 적용된 RGB 0~1**이다. 선형 ProPhoto 또는 로그 영상 입력용 LUT가 아니다.

파일의 샘플 순서는 R축이 가장 빠르게 변하고 G, B가 뒤따른다. 로딩 후 배열은 `[R, G, B, 출력 채널]`로 정렬한다. 각 셀을 여섯 사면체로 나누고 입력의 소수 좌표 순서로 포함 사면체를 정한다. 단위 LUT 외에 임의 꼭짓점 값으로 여섯 경우를 독립 검증한다.

파서는 다음을 거절한다.

- 1D LUT, 알 수 없는 헤더, 중복 헤더, 샘플 뒤에 나오는 헤더.
- 0~1이 아닌 DOMAIN, 유한하지 않은 값, 범위를 벗어난 출력.
- 격자와 다른 샘플 수, manifest와 다른 격자 또는 SHA-256.
- 지원되지 않는 스타일 ID, 버전, 기준 현상 버전, 색공간 계약.

프로필이 없거나 손상되면 목록의 `available`을 `false`로 하고 원인을 반환한다. 요청한 프로필 대신 다른 스타일을 적용하지 않는다. 캐시에 LUT가 있어도 적용 전 자산의 SHA-256을 재검사한다.

스타일 강도는 인코딩된 sRGB에서 `기본 × (1-strength) + 스타일 × strength`로 혼합한다. 0은 부동소수점 값이 정확히 같은 기본 결과를 반환하고 1은 전체 스타일 결과를 반환한다. 입자는 이 혼합과 별개의 단계다.

## 흑백 스타일

흑백 초기 스타일은 RGB를 선형 sRGB로 되돌린 뒤 R/G/B에 각각 `0.25/0.65/0.10`을 곱해 흑백 휘도를 구한다. 이를 sRGB로 인코딩하고 `monochrome/curve.json`에 정의한 흑백 전용 단조 곡선을 적용한다. 출력의 세 채널은 같은 값이다. RGB 평균이나 채도 0만으로 구현하지 않았다.

스타일 강도가 100% 미만이면 기본 컬러와 흑백을 혼합하므로 색이 일부 남을 수 있다. 흑백을 선택하면 추가 채도 보정은 무시한다.

## 추가 보정

- 노출과 상대 WB는 RAW 단계에서만 적용한다.
- 대비는 인코딩된 sRGB에서 끝점을 유지하는 S 곡선으로 처리한다.
- 하이라이트/그림자는 인코딩된 휘도 마스크로 명암을 조절한다. 양수는 해당 영역을 밝게 한다.
- 채도는 sRGB를 선형화한 뒤 휘도와의 차이를 조절하고 색역을 압축한다. 마지막에 sRGB로 다시 인코딩한다.
- 모든 추가 보정이 0이면 입력과 정확히 같은 값을 반환한다.

명암 보정은 촬영되지 않은 정보를 복원하는 기능이 아니다.

## 크기와 입자

`resize_rgb()`는 각 채널을 Pillow의 부동소수점 `F` 모드로 Lanczos 축소한다. 확대를 하지 않으며, 8비트 중간 이미지를 만들지 않는다. 입자는 최종 출력 크기로 축소한 뒤 추가한다.

입자는 원본 SHA-256과 레시피의 seed를 SHA-256으로 결합하고, 원본 환산 좌표를 입력으로 받는 정수 해시 잡음으로 만든다. 난수 스트림을 순서대로 소비하지 않으므로 작업 순서와 타일 순서가 달라도 패턴이 같다. 작은 입자는 원본 1.25픽셀, 큰 입자는 3픽셀 크기의 격자를 사용한다. 격자 사이를 연속 보간하며, 밝기에 따라 진폭을 조절한다. 축소 시 픽셀 면적에 따른 진폭 감소를 적용한다. 이는 필름 느낌을 위한 사진 입자의 초기 근사다.

`apply_grain(rgb, settings, source_hash, original_size=(원본 너비, 원본 높이), origin=(원본 x, 원본 y))`를 호출한다.

- 전체 이미지의 축소본은 원본/출력 크기로 좌표 배율을 추정한다.
- 원본 크기 타일은 **모든 타일에서** `settings['_grain_scale']=1`을 전달한다. 첫 타일의 `(0,0)`도 포함한다.
- 축소 타일은 `_grain_scale=(원본 픽셀/출력 픽셀의 x 배율, y 배율)`과 원본 좌표 origin을 전달한다.
- `_grain_scale`은 내부 실행 인자이며 사용자 레시피의 설정 항목이 아니다.

동일한 출력 크기와 좌표에서 타일 결과가 전체 결과와 비트 단위로 일치하는지 테스트한다. 서로 다른 출력 크기의 입자는 원본 좌표와 크기 인상을 공유하며 픽셀별 일치를 요구하지 않는다.

## 메모리

색 변환, 추가 보정, LUT 보간과 입자 연산의 내부 임시 배열은 기본 262,144픽셀 단위로 제한한다. 호출 함수는 입력과 결과 배열을 보유하므로 전체 작업 메모리는 RAW 엔진의 memmap과 직렬 처리 정책도 함께 고려해야 한다. 축소는 채널별로 수행한다.

## 프로필 출처와 검증 한계

포함 프로필은 필름 느낌을 표현하기 위해 이 프로젝트에서 작성한 수학적 변환이다. 자산은 동봉한 MIT 라이선스로 사용·수정·재배포할 수 있다.

`python tools/generate_profiles.py`로 모든 LUT, 곡선, manifest를 재생성한다. 생성기는 고정 격자와 수식, 출력 소수점 자릿수를 사용한다. 테스트는 재생성한 파일과 포함 자산의 바이트 일치를 검사한다. 변경 시 스타일 버전과 해시를 함께 갱신한다.

각 컬러 스타일은 고유한 곡선과 색상별 처리를 가진다.

| 스타일 | 초기 구현 |
|---|---|
| 다큐멘터리 (`documentary`) | 절제된 채도, 차가운 그림자, 빨강 영역과 따뜻한 하이라이트 |
| 네거티브 (`negative`) | 깊은 저명부, 밝기에 따른 색 교차, 초록 영역의 별도 변형 |
| 시네마 (`cinema`) | 들어 올린 검정과 완만한 흰색, 낮은 채도, 노랑 영역 완화 |
| 비비드 (`vivid`) | 강한 명암, 파랑·초록 영역의 채도 강화, 따뜻한 색의 증가량 제한 |
| 흑백 (`monochrome`) | 선형 RGB별 명도 가중치, 흑백 전용 곡선, 밝기별 입자 진폭 |

현재 전부 **초기 스타일**이다. 통제된 참고 사진, 보정용 40장과 별도 검증용 20장은 제공되지 않았다. 따라서 ΔE00, 피부색 품질, 사용자 평가 4/5 충족 여부는 아직 검증되지 않았다. 실제 기준 촬영과 별도 검증을 마친 프로필만 “참고 사진으로 조정됨”으로 표시해야 한다.

단위 테스트는 수치 처리, 파일 계약, 재현성과 정밀도를 검증한다. a6400 실제 촬영 세트에 대한 색감 평가나 성능 P95 측정을 대신하지 않는다.
